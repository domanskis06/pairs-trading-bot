# pairs-trading-bot

Statistical arbitrage bot: finds cointegrated pairs of assets and trades the spread mean-reversion (z-score entry/exit, hedge ratio via OLS/Kalman).

## Environment
- Python 3.12, virtualenv at `.venv/`. Activate with `source .venv/bin/activate`.
- Install deps: `pip install -r requirements.txt`.
- Secrets (API keys, broker credentials) go in `.env`, never committed — see `.gitignore`.

## Repo structure
- `data/` — fetching/caching price data (source code, e.g. `loader.py`).
- `pairs/` — pair screening, cointegration tests (Engle-Granger/Johansen, ADF).
- `signals/` — spread calculation, z-score, entry/exit signal logic.
- `backtest/` — the backtesting engine (simulates trades over historical data).
- `risk/` — position sizing, stop-loss, exposure limits.
- `execution/` — broker/paper-trading interface (built last, after backtest is trusted).
- `analysis/` — performance metrics (Sharpe, drawdown, win rate), plots.
- `config.py` — all strategy parameters (lookback, z-score thresholds, stop-loss). Never hardcode these inline elsewhere.
- `data_cache/` — downloaded market data (CSV/parquet), gitignored, regenerated by `data/`.

## Data files — do not read
- Never open/read files under `data_cache/`, nor any `*.csv`/`*.parquet` in this repo, unless the user explicitly asks to inspect one. They're large downloaded datasets, not source — reading them burns tokens for no benefit. Inspect data via a short Python snippet (`.head()`, `.describe()`, `len()`) instead of reading the raw file.

## Conventions
- Keep data fetching, pair selection, signal generation, and backtesting/execution as separate modules — don't mix them in one script.
- Any strategy parameter (lookback window, entry/exit z-score thresholds, stop-loss) belongs in `config.py`, not as a magic number inline.
- Backtests must be reproducible: fix random seeds, pin the data date range explicitly.
- No look-ahead bias: signal/backtest code may only use data available up to the current bar (rolling windows, not full-series stats).

## Testing
- `pytest` for unit tests (e.g. spread calculation, cointegration test wrappers, signal logic).
- No live-money execution paths should run under test — mock/stub the broker API.
